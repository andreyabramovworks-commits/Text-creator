# Block patterns: choose by evidence and decision

These are original writing models, not copy to paste unchanged. Square brackets are data to obtain from the business. If the value is unknown, keep the bracket in a draft or omit the claim.

| Block | Use when | Structure | Reject when |
|---|---|---|---|
| Hero | Visitor needs immediate orientation | Audience/use case + concrete outcome + mechanism + action | Category, audience, or outcome is unknown |
| Feature card | A capability changes a decision | Verb/noun heading + what it does + practical implication | All cards repeat one generic benefit |
| Process | How the service works is a buying objection | Step + input + output + owner | Steps or timing are invented |
| Case study | One relevant example can substantiate a claim | Context + intervention + observed result + scope | The result cannot be checked or shared |
| Price | Visitor compares costs and limits | Amount + period + inclusions + key exclusions + CTA | Hidden conditions change the displayed cost |
| FAQ | A real objection remains after core blocks | Question in user's words + direct answer + condition/next step | It hides a material caveat |
| Form | Visitor is ready to act | Task heading + minimum fields + action + expectation | An input has no defined purpose |
| Final CTA | Visitor has enough information | Decision recap + matching action | It introduces a new promise |

## Hero: four useful shapes

**Known category.** “Платформа для [задача] команды [аудитория]” / “A [category] for [audience] to [task].” Use if category terms are familiar. Support with a differentiator that is verifiable.

**Outcome first.** “[Результат] без [реальная трудность]” / “[Outcome] without [documented obstacle].” Use only when both parts reflect product evidence; avoid absolute promises.

**Service deliverable.** “[Тип работы] для [аудитория]: от [вход] до [выход]” / “[Service] for [audience], from [input] to [deliverable].” Add scope and process near the heading.

**High-risk purchase.** “[Категория] с [ключевое проверяемое условие]” / “[Category] with [verifiable requirement].” Follow with security, procurement or implementation evidence, not adjectives.

## CTA choice

| Visitor readiness | Action model | Destination check |
|---|---|---|
| Exploring | «Посмотреть пример» / “See an example” | Opens a real example |
| Evaluating | «Сравнить тарифы» / “Compare plans” | Shows meaningful differences and terms |
| Ready to trial | «Начать пробный период» / “Start a trial” | Trial exists; card states billing requirements |
| Complex sale | «Обсудить задачу» / “Discuss your project” | Form/booking reveals what happens next |

## Trust block selection

1. If the claim is about **product behavior**, show a real screenshot, demo, specification, or documented workflow.
2. If the claim is about **business results**, show a case with baseline, period, method and approval.
3. If the claim is about **customer satisfaction**, use an attributable review with permission and context.
4. If the claim is about **security or compliance**, name the current standard, scope and proof; do not use a generic shield icon as evidence.
5. If none is available, explain the process and make proof collection an open task.

The truth and disclosure principle for endorsements is supported by [FTC guidance](https://www.ftc.gov/news-events/topics/truth-advertising/advertisement-endorsements). Apply the law of the market in question.

## FAQ answer shapes

- **Yes/no with condition:** “Да, если [condition]. [Action/limitation].” / “Yes, if [condition]. [Action/limit].”
- **Process:** “[First step]. [Who does what]. [What the visitor receives].”
- **Cost:** “[Amount or pricing rule]. [Billing period]. [Included/excluded]. [Where exact terms live].”
- **Risk:** “[Policy-backed answer]. [Exception]. [Recovery/contact path].”

Use the customer's question wording from interviews, support or search queries where available. The [GOV.UK writing guidance](https://www.gov.uk/service-manual/design/writing-for-user-interfaces) informs scannability and plain language; it does not establish the business answer.
